# VPP 流量可视化引擎 - 需求文档

## 介绍

为VPP实时监控仪表板添加一套完整的流量渲染引擎，使观众能够在3D拓扑图中"看到"网络中的数据流动。通过粒子流、发光效果、大小变化等视觉元素，直观展示VPP系统中各组件之间的通信情况。

## 需求

### 需求1：OVS流量采集

**用户故事**：作为系统监控员，我需要实时采集OVS镜像端口导出的网络流量数据，以便进行可视化展示。

#### 接受标准

1. WHEN OVS镜像端口启动时，THE 系统应该能够读取PCAP或JSON摘要数据
2. WHEN 读取流量数据时，THE 数据应包含：源IP、目的IP、协议类型、报文长度、时间戳
3. WHEN 流量数据到达时，THE 系统应该在100ms内处理并转化为事件
4. WHEN 处理失败时，THE 系统应该记录错误但继续处理后续数据
5. WHEN 系统启动时，THE 系统应该自动连接到OVS镜像端口

### 需求2：流量事件转化

**用户故事**：作为可视化引擎，我需要将原始网络流量转化为标准化的事件流，以便前端进行渲染。

#### 接受标准

1. WHEN 流量数据被采集时，THE 系统应该转化为标准事件格式：`{ "from": "source", "to": "destination", "type": "Control|Telemetry", "intensity": 0.0-1.0, "packet_size": bytes, "timestamp": ISO8601 }`
2. WHEN 转化事件时，THE 系统应该识别流量类型（控制指令vs遥测数据）
3. WHEN 转化事件时，THE 系统应该计算流量强度（基于报文频率和大小）
4. WHEN 事件生成时，THE 系统应该通过WebSocket实时推送到前端
5. WHEN 事件队列满时，THE 系统应该采用FIFO策略丢弃最旧的事件

### 需求3：WebSocket实时推送

**用户故事**：作为前端应用，我需要通过WebSocket接收实时的流量事件，以便进行动画渲染。

#### 接受标准

1. WHEN 客户端连接时，THE 服务器应该建立WebSocket连接
2. WHEN 有新的流量事件时，THE 服务器应该在50ms内推送到所有连接的客户端
3. WHEN 连接断开时，THE 服务器应该自动清理资源
4. WHEN 客户端重连时，THE 服务器应该恢复连接并继续推送
5. WHEN 推送失败时，THE 系统应该记录错误但不中断其他连接

### 需求4：3D拓扑图渲染

**用户故事**：作为观众，我需要看到一个暗色背景的3D拓扑图，显示VPP系统中各组件的位置和连接关系。

#### 接受标准

1. WHEN 仪表板加载时，THE 3D场景应该显示所有VPP组件（VCC Master、Power、Storage、Demand）
2. WHEN 场景加载时，THE 组件应该按照逻辑关系排列成拓扑图
3. WHEN 用户交互时，THE 用户应该能够旋转、缩放、平移3D场景
4. WHEN 场景渲染时，THE 帧率应该保持在60fps以上
5. WHEN 组件状态变化时，THE 组件的颜色或外观应该实时更新

### 需求5：粒子流动画

**用户故事**：作为观众，我需要看到代表报文的粒子在3D拓扑图中流动，直观展示数据传输过程。

#### 接受标准

1. WHEN 有流量事件时，THE 系统应该在源组件和目标组件之间生成粒子流
2. WHEN 生成粒子时，THE 粒子大小应该与报文长度成正比（大报文=大粒子）
3. WHEN 生成粒子时，THE 粒子流速应该与报文频率成正比（频繁=快速）
4. WHEN 粒子到达目标时，THE 粒子应该消失或被吸收
5. WHEN 场景中粒子过多时，THE 系统应该自动优化性能（合并或删除旧粒子）

### 需求6：控制指令可视化

**用户故事**：作为观众，我需要区分控制指令和遥测数据，以便理解系统的协调过程。

#### 接受标准

1. WHEN 流量类型为"Control"时，THE 粒子应该带有发光效果（Glow/Bloom）
2. WHEN 流量类型为"Control"时，THE 粒子颜色应该为暖色（红/橙/黄）
3. WHEN 流量类型为"Telemetry"时，THE 粒子应该半透明（Alpha < 0.7）
4. WHEN 流量类型为"Telemetry"时，THE 粒子颜色应该为冷色（蓝/青/绿）
5. WHEN 粒子流动时，THE 发光效果应该随着流量强度变化

### 需求7：流量统计展示

**用户故事**：作为系统分析员，我需要看到实时的流量统计信息，以便分析系统性能。

#### 接受标准

1. WHEN 仪表板显示时，THE 应该显示总流量统计（总报文数、总字节数）
2. WHEN 统计更新时，THE 应该显示各组件间的流量分布
3. WHEN 统计更新时，THE 应该显示控制指令和遥测数据的比例
4. WHEN 用户选择时间范围时，THE 应该显示该时间范围内的统计数据
5. WHEN 统计数据更新时，THE 应该在500ms内刷新显示

### 需求8：性能优化

**用户故事**：作为系统管理员，我需要确保可视化引擎在高流量情况下仍能保持良好性能。

#### 接受标准

1. WHEN 流量高峰时，THE 系统应该能够处理每秒1000+个事件
2. WHEN 渲染3D场景时，THE 帧率应该保持在30fps以上（即使在高流量下）
3. WHEN 内存使用时，THE 系统应该限制粒子数量不超过10000个
4. WHEN WebSocket推送时，THE 延迟应该 < 100ms
5. WHEN 系统运行时，THE CPU使用率应该 < 50%

### 需求9：交互功能

**用户故事**：作为观众，我需要能够与可视化场景交互，以便更好地理解系统运行情况。

#### 接受标准

1. WHEN 用户点击组件时，THE 系统应该显示该组件的详细信息
2. WHEN 用户悬停在粒子流上时，THE 系统应该显示流量详情（源、目标、大小、类型）
3. WHEN 用户选择时间范围时，THE 系统应该回放该时间范围内的流量
4. WHEN 用户暂停时，THE 系统应该暂停粒子动画但保留当前状态
5. WHEN 用户调整速度时，THE 系统应该加快或减慢粒子流动速度

### 需求10：数据导出

**用户故事**：作为系统分析员，我需要能够导出可视化数据和截图，以便进行离线分析。

#### 接受标准

1. WHEN 用户请求截图时，THE 系统应该生成当前3D场景的高分辨率截图
2. WHEN 用户请求视频时，THE 系统应该录制可视化过程并导出为MP4格式
3. WHEN 用户请求数据时，THE 系统应该导出流量事件数据为JSON格式
4. WHEN 导出时，THE 系统应该包含时间戳和元数据
5. WHEN 导出完成时，THE 系统应该提供下载链接

## 非功能需求

### 性能
- 流量采集延迟 < 100ms
- 事件转化延迟 < 50ms
- WebSocket推送延迟 < 100ms
- 3D渲染帧率 >= 30fps（高流量）/ >= 60fps（正常）
- 粒子数量限制 <= 10000个

### 可靠性
- 流量采集失败应该自动重连
- WebSocket连接断开应该自动重连
- 系统应该能够处理网络抖动
- 数据应该不丢失（使用缓冲队列）

### 可扩展性
- 支持多个OVS镜像端口
- 支持自定义流量分类规则
- 支持自定义粒子渲染效果
- 支持自定义拓扑图布局

### 用户体验
- 界面应该直观易用
- 交互应该流畅响应
- 视觉效果应该美观吸引
- 信息展示应该清晰明了

## 接受标准总结

所有10个需求必须满足，且：
- 单元测试覆盖率 >= 80%
- 集成测试覆盖所有流量采集和渲染路径
- 性能测试验证所有性能指标
- 完整的API文档
- 完整的用户指南
- 美观的UI/UX设计
